## 最终确认的梦境窥视规则

- **已打开金库：不允许窥视，直接隐藏目标，不置灰。** 引擎同时拒绝此请求，不消耗卡牌。
- **未打开金库：可以再次窥视同一金库。** 是否曾经窥视、是否已记住内容，都不影响再次选择。
- 目标层横向排列，使用完整原卡，不再显示“点击选择此层”等提示；鼠标悬停为手型，选择后点击“确认”。
- 没有合法目标时显示“无可选目标层”，确认不可用；显式空目标列表不会回退成全部层。

这里的“已打开”依据引擎 `vault.isOpened`，与“本人曾窥视”是两个状态。此前将已打开金库也保留为候选的理解已撤回；本次约定同样应用于前端列表与引擎校验。

引擎的黄金轨迹因旧轨迹中的窥视请求现在被拒绝而变化，已按测试约定更新 `goldenTrace.baseline.txt`，仅 `n=4 seed=s4-7` 一局变化，其余 69 局不变；提交说明记录这一规则变更。金库内容、贿赂成败与阵营信息仍通过既有权限视图裁剪，不放入公共事件。

## 这几轮落实的交互

### 玩家与层卡

复用 `PlayerAvatar`、`PlayerName`：左侧玩家、层卡头像、选目标玩家和手机同桌信息使用同一套呈现。头像采用原型裁片或原卡头部裁切，固定正圆；默认 1px 灰边，高亮 3px 金边。层卡上的高亮改为白色与深色组合，提高彩色底纹上的辨识度；当前层也采用同样的明暗边框。

点击头像打开对应角色说明；选择目标玩家通过旁边的目标行完成，避免阅读角色时误选。默认名字为“玩家名 · 角色名”，行动中、层数、手牌与应答状态另起一行。药剂师按原卡头部位置单独校准裁切，并移除旧选择器对头像圆点的拉伸覆盖。

### 手牌操作与弹层

无手牌时，结束行动、跳过弃牌和抽牌等当阶段操作显示在手牌区中央；不再显示无效的选牌提示。技能按钮在左，主要操作按钮在右并使用主按钮样式。桌面与手机复用操作逻辑。

解封响应、角色应答和技能选择统一使用居中弹层，移除旧手机内联响应条。需要选牌／选层的后续弹层打开时，先前应答层收起，避免重复遮罩；必须处理的应答不能靠 Esc 或点击遮罩取消。

掷骰读取真实引擎结果，翻滚约 0.85 秒，随后保留结果 2 秒自动收起，不再要求点击“继续结算”；减少动效时不播放翻滚，结果仍保留 2 秒。保留主动收起和结果回看入口。

### 自动抽牌

自动抽牌默认启用，通过 `ico:draw:prefs` 保存本机偏好。本人进入抽牌阶段且没有可发动的抽牌技能时，客户端立即请求正常抽牌；有可发动技能时保留快捷入口与普通抽牌选择。

服务端与本地 Worker 共用 `DRAW_TIMEOUT_MS = 5000`：选择期间显示倒计时，5 秒到期正常抽牌。立即自动抽牌会提前离开抽牌阶段，不触发这次超时代发；抽牌到期不会累计挂机次数。技能选择弹层随回合／阶段变化失效，避免超时后继续提交旧阶段技能。固定调试场景不自动发 move。
